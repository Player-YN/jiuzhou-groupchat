## 阶段 P0 — 骨架 + 单 Agent 跑通

### 目标
- 跑通最小可运行闭环:**浏览器发一条消息 → 后端调 1 个 LLM → 流式推回前端 → 前端"打字机"显示**
- 不涉及多 Agent、不涉及讨论、不涉及纪要
- 验证 3 件事: WebSocket 双向通信、LangGraph 集成、流式渲染

### 任务清单

- [ ] **T0.1** 初始化项目目录 (backend/ + frontend/) + Docker Compose 骨架
- [ ] **T0.2** backend: `pyproject.toml` 配 FastAPI + Uvicorn + LangGraph + LangChain + SQLModel
- [ ] **T0.3** backend: 实现 FastAPI `WebSocket /ws/{session_id}` endpoint,能接收文本帧并 echo 回来
- [ ] **T0.4** backend: 实现最简 `StateGraph` — 1 个节点 + ChatModel,支持 `graph.stream(..., stream_mode="custom")`
- [ ] **T0.5** backend: 把 `writer({chunk: "..."})` 事件桥接到 WebSocket 推送给前端
- [ ] **T0.6** frontend: Next.js 15 项目初始化 + Tailwind + shadcn/ui 装好
- [ ] **T0.7** frontend: 实现 `useWebSocket` hook (含自动重连 + 心跳)
- [ ] **T0.8** frontend: 实现 `StreamingText` 组件 — 收到 chunk 就 append,有光标闪烁
- [ ] **T0.9** frontend: 一个最简 ChatRoom 页面,输入框 + 消息列表 + 1 个 AI 头像
- [ ] **T0.10** 端到端手测:用户输入 → 1 秒内看到 AI 开始打字 → 3-5 秒看到完整回复

### 硬性 Eval Gate

| 编号 | 验收项 | 验证方法 | 通过标准 |
|---|---|---|---|
| **G0-1** | 后端能启动 | `cd backend && uvicorn app.main:app --reload` | 无 traceback,监听 8000 端口 |
| **G0-2** | 前端能启动 | `cd frontend && npm run dev` | 无报错,3000 端口可访问 |
| **G0-3** | WS 连通 | 浏览器 console `new WebSocket('ws://localhost:8000/ws/test')` | 立即收到 `{type:"session_init"}` |
| **G0-4** | 单轮回复 | 浏览器输入 "你好",5s 内 | 看到完整 AI 回复(单条消息,非流式也通过) |
| **G0-5** | 流式输出 | 同上 | 收到 ≥ 3 个 `agent_msg_chunk` 才收到 `agent_done`(证明是真流式,不是攒完一起推) |
| **G0-6** | 打字机效果 | 肉眼观察 | 看到逐字出现 + 光标闪烁,不是整段"啪"地一下出现 |
| **G0-7** | 重连 | 手动 `kill` 后端 5s 再起 | 前端 30s 内自动重连,无需刷新页面 |
| **G0-8** | 配置文件 | 仓库根 `README.md` | 包含 "环境变量 + 启动命令 + 端口号" 三件套 |

### 估时
**3 人天**

## 阶段 P1 — 多 Agent + 调度 + 群聊

### 目标
- 4 个 AI 角色 (Host/Creator/Critic/Summarizer) 能在同一聊天室互动
- 主持人 Agent 调度下一位发言者
- 用户可 @ 某 AI,被 @ 的 AI 优先回应
- 一个 topic 下能跑 ≥ 5 轮有意义讨论

### 任务清单

- [ ] **T1.1** backend: 定义 `State` TypedDict (含 `messages: Annotated[list, add]`、`next_speaker`、`round_count`)
- [ ] **T1.2** backend: 实现 4 个角色 Agent node (host/creator/critic/summarizer),每个用独立 prompt 文件
- [ ] **T1.3** backend: 实现 Supervisor node — 用 LLM 决策 `next_speaker`,规则见 02_架构设计 §5.1
- [ ] **T1.4** backend: 用 `add_conditional_edges` 串起 Supervisor → 4 个 Agent → 回 Supervisor
- [ ] **T1.5** backend: 用户消息含 `@Creator` 时,Supervisor 优先返回 `Creator`
- [ ] **T1.6** backend: 加 InMemorySaver checkpointer,支持 `graph.get_state(config)` 查询
- [ ] **T1.7** backend: 把 4 个 Agent 的事件分别推 `agent_msg_chunk` (前端能区分谁在说)
- [ ] **T1.8** backend: 用户消息持久化到 SQLite (session_id + message_id + role + text + ts)
- [ ] **T1.9** frontend: `MessageBubble` 组件按 `agent` 字段显示不同头像 + 颜色
- [ ] **T1.10** frontend: `TopicInput` 组件,新建会话时输入 topic
- [ ] **T1.11** frontend: 支持 `@` 触发 (输入 `@C` 自动补全为 `@Creator`)
- [ ] **T1.12** frontend: "X 正在思考..." loading 状态 (收到 `agent_thinking` 时显示)
- [ ] **T1.13** 端到端: 用 topic "AI 健身教练" 跑通 ≥ 5 轮讨论
- [ ] **T1.14** 编写 pytest 基础测试 (`test_graph.py`: Supervisor 决策正确 / 4 个 Agent 都能被调度 / 5 轮后状态正确)

### 硬性 Eval Gate

| 编号 | 验收项 | 验证方法 | 通过标准 |
|---|---|---|---|
| **G1-1** | 4 个 Agent 都能说话 | 手动测试,分别 `@Host` `@Creator` `@Critic` `@Summarizer` | 每个 Agent 至少 1 次能产出可见消息 |
| **G1-2** | @ 触发优先级 | `@Creator` 后,下一个发言者 80% 是 Creator | 跑 5 次至少 4 次命中 |
| **G1-3** | 主持人调度 | 用户无 @ 时,讨论至少 3 轮 | Supervisor 选不同 Agent,不全是一个人霸场 |
| **G1-4** | 5 轮深度讨论 | topic "AI 健身教练" 跑 1 次 | 数据库 `messages` 表行数 ≥ 12 (4 角色 × 3 轮 + 用户 2 次) |
| **G1-5** | 消息区分 | 前端 UI 截图 | 4 种不同头像/颜色,不混淆 |
| **G1-6** | 思考状态 | 录屏 | 看到"小创正在思考..." → 3-5s 后开始打字 |
| **G1-7** | Checkpoint 持久 | `python -c "from app.graph import graph; print(graph.get_state({'configurable':{'thread_id':'1'}}))"` | 能拿到完整 state |
| **G1-8** | pytest | `pytest backend/tests -v` | 所有用例 pass,覆盖 4 个 Agent + Supervisor 决策 |
| **G1-9** | pytest 覆盖率 | `pytest --cov=app --cov-report=term-missing` | `app/graph/` 覆盖率 ≥ 70% |
| **G1-10** | 无 PII 泄露 | 手动检查 4 个 prompt | 无硬编码 API key、邮箱、手机号 |

### 估时
**5 人天**

### 产出物
- 4 角色群聊可运行 Demo
- 一段 30s 录屏(展示 5 轮讨论 + 流式效果)

## 阶段 P2 — 纪要导出 + 部署 + 验收

### 目标
- 讨论结束自动生成结构化纪要(主持人说 `[CALL_SUMMARIZER]` 触发)
- 一键导出纪要为 Markdown / JSON 文件
- Docker Compose 一键起前后端
- 达到简历作品集级别的"完成度"

### 任务清单

- [ ] **T2.1** backend: Summarizer Agent 严格用 Pydantic schema 输出 JSON (用 `output_json=SummaryModel`)
- [ ] **T2.2** backend: 校验 JSON 合法 (字段非空、list 长度合理),不合法则重试 1 次
- [ ] **T2.3** backend: 纪要存 `summaries` 表,关联 session_id
- [ ] **T2.4** backend: 提供 `GET /api/sessions/{id}/summary` REST 接口 (兜底,WS 失败也能取)
- [ ] **T2.5** backend: 实现 `interrupt` 消息类型 (用户能打断当前 Agent)
- [ ] **T2.6** backend: 实现 `vote` 消息类型 (点赞/踩)
- [ ] **T2.7** backend: 完善异常处理 (LLM 超时、JSON 解析失败、WS 断线)
- [ ] **T2.8** frontend: `SummaryCard` 组件 — 渲染 JSON 纪要为漂亮卡片
- [ ] **T2.9** frontend: "导出为 Markdown" / "导出为 JSON" 按钮
- [ ] **T2.10** frontend: 讨论侧边栏 (sessions 列表 + 历史回看)
- [ ] **T2.11** frontend: 移动端响应式 (Tailwind 适配 ≤ 768px)
- [ ] **T2.12** frontend: 加暗色模式 (Tailwind dark:)

## 总计 & 风险

### 估时汇总
| 阶段 | 估时 |
|---|---|
| P0 — 骨架 + 单 Agent | 3 人天 |
| P1 — 多 Agent + 调度 | 5 人天 |
| P2 — 纪要 + 部署 + 验收 | 5 人天 |
| **合计** | **13 人天** ✅ (< 15 上限) |

### 关键风险

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| LangGraph 流式 API 文档不全 | 中 | 中 | P0 阶段先写 1 个最小 demo 验证,跑不通就回退 CrewAI |
| LLM API 限流 / 余额不足 | 中 | 高 | P0 就接 DeepSeek 备用,Ollama 本地兜底 |
| 前端打字机效果卡顿 | 低 | 中 | 用 `requestAnimationFrame` 节流,每 16ms 最多更新一次 DOM |
| Checkpointer 序列化大对象慢 | 中 | 低 | MVP 用 InMemorySaver,生产再换 PostgresSaver |
| 4 个 Agent 讨论跑题 | 高 | 中 | Host prompt 加严格指令,每 2 轮 Host 强制拉回 |

### 阶段暂停 / 回退点

- **P0 结束** G0-1 ~ G0-8 全过 → 进 P1;否则继续修
- **P1 结束** G1-1 ~ G1-10 全过 → 进 P2;若 G1-4 (5 轮讨论) 失败,考虑减到 3 轮
- **P2 结束** G2-1 ~ G2-18 全过 → 可发布;若 G2-11 (Lighthouse) 没过,优化后端响应 / 前端图片
