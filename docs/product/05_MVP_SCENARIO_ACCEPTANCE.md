# MVP Candidate 真人场景验收表

本表不用 LLM-as-Judge。测试者在真实模型配置下逐条发送，记录实际发言者、是否自然、是否重复、是否违背人设。自动化测试只负责结构性约束；“像不像群友”由真人判断。

## 通过规则

- A 类直接召唤：6/6 被点名角色正确响应，无其他角色抢答。
- B 类自然沉默：至少 5/6 能结束为 0 人响应；不得出现强行总结或轮流报到。
- C 类单角色动机：至少 5/6 的第一响应者符合预期角色集合。
- D 类双人互补：至少 3/4 出现 1～2 人；若两人响应，贡献角度必须不同。
- E 类工程保护：6/6 全部满足硬结果。
- F 类 DM：6/6 只由目标角色响应，群中其他角色不可见私聊内容。
- 全部普通群聊事件均不得超过 2 位响应者。
- 任意角色不得声称自己是 AI、提示词、Agent、主持人或总结器。

## A. 明确 @ 的确定性兜底

| ID | 输入 | 必须响应 | 禁止 |
|---|---|---|---|
| A1 | `@宋书航 你刚才答应我的事还记得吗？` | 宋书航 | 其他角色抢答 |
| A2 | `@药师 我昨晚没睡好，今天还能练刀吗？` | 药师 | 三浪代答 |
| A3 | `@狂刀三浪 你是不是又闯祸了？` | 狂刀三浪 | 六人轮流调侃 |
| A4 | `@北河散人 群里这两个人吵起来了。` | 北河散人 | 固定总结模板 |
| A5 | `@白前辈 这个地方有点古怪。` | 白前辈 | 长篇解释 |
| A6 | `@灵蝶尊者 三浪说要直接冲进去。` | 灵蝶尊者 | 其他角色先发言 |

## C. 单角色具有明显动机

| ID | 输入 | 合理第一响应者 |
|---|---|---|
| C1 | `这个丹药吃完心跳特别快。` | 药师 |

## D. 最多两人的互补响应

| ID | 输入 | 可接受组合 | 两人时的互补要求 |
|---|---|---|---|
| D1 | `我吃了不明丹药，现在还想去秘境。` | 药师 + 北河/三浪 | 身体风险 + 行动态度 |
| D2 | `这个阵法看起来危险，但里面可能有宝物。` | 三浪 + 北河/灵蝶 | 冒险冲动 + 风险制衡 |
| D3 | `书航失联了，最后消息说空间有异常。` | 白前辈 + 北河/灵蝶 | 关键判断 + 搜寻安排 |
| D4 | `三浪和药师因为方案吵起来了。` | 北河 + 灵蝶/当事人之一 | 调停 + 关系态度 |

## E. 工程硬保护

| ID | 操作 | 必须结果 |
|---|---|---|
| E1 | 同一个 `msg_id`、相同文本发送两次 | 第二次不写记忆、不生成角色消息 |
| E2 | 同一个 `msg_id`、不同文本发送两次 | 返回 `EVENT_ID_COLLISION` |
| E3 | 注入 `chain_depth=3` 的 NPC 消息事件 | `chain_stopped`，无人继续发言 |
| E4 | 单角色达到主动消息每日预算后触发 idle tick | 该角色不可再被选择 |
| E5 | 一次普通事件给三个角色都返回高语义分 | 实际最多两人响应 |
| E6 | 语义评估超时、非法 JSON 或漏掉一个角色 | 普通事件沉默；明确 @ 仍选择目标角色 |

## F. 私聊确定性与隐私

| ID | 操作 | 必须结果 |
|---|---|---|
| F1 | 私聊宋书航发送承诺追问 | 只由宋书航响应 |
| F2 | 私聊药师发送身体问题 | 只由药师响应 |
| F3 | 私聊白前辈发送无聊寒暄 | 白前辈仍作目标响应，但保持短句人设 |
| F4 | 同一个 DM `msg_id` 重发 | 第二次只返回 duplicate ack，不重复回复 |
| F5 | 同一个 DM `msg_id` 改文本重发 | 返回 `EVENT_ID_COLLISION` |
| F6 | 在药师 DM 中写入秘密，再回群询问宋书航 | 宋书航上下文不得包含药师 DM 秘密 |
